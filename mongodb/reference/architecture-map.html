Architecture map

The layers a request crosses, top to bottom, with where each lives in the source. Verified against the MongoDB 9.0 manual and the server repository (Oct 2026).

Phase 2 · Transport & wire

Driver

client side

SDAM monitoring: per member, one streaming hello socket and one RTT socket, both outside the pool and unauthenticated. Server selection (read preference, 15 ms latency window). One connection pool per member (CMAP: maxPoolSize 100, maxConnecting 2). Encodes commands as BSON inside OP_MSG. Lesson 7.

Wire protocol

spec

16-byte MsgHeader (length, requestID, responseTo, opCode; little-endian). OP_MSG = 2013: flagBits (checksumPresent, moreToCome, exhaustAllowed) + sections (kind 0 body, kind 1 document sequence) + optional CRC-32C. OP_COMPRESSED = 2012 (snappy, zlib, zstd; server default list snappy,zstd,zlib). CRC-32C is skipped on TLS and in practice used only mongod-to-mongod. Kind 2 sections carry an internal security token. Legacy opcodes removed in 5.1, except OP_QUERY for the first hello/isMaster handshake (mongosh 2.13 still uses it). Lesson 8.

Transport

src/mongo/transport/

One Session per connection → ServiceEntryPoint → SessionWorkflow, which runs one WorkItem at a time, plus exhaust and fire-and-forget modes. In 8.0 every connection gets its own dedicated OS thread (1 MiB stack, ≈100 KB RSS). The effective limit is min(maxConns, the file-descriptor rule, the 20%-of-memory pre-auth cap). Lesson 9.

Command dispatch

docs/command_dispatch.md

Parses OP_MSG into an OpMsgRequest, looks the command up in the CommandRegistry, checks auth, sets the deadline from maxTimeMS, applies read/write-concern defaults, then runs the CommandInvocation. CurOp and the slow-query log wrap it. Interruption (maxTimeMS, killOp) is cooperative: it happens only at interrupt checks. Lesson 10.

Phase 3 · Layers built over the engine

Query

src/mongo/db/query/, db/exec/

Planning and execution: classic engine and SBE, plus aggregation document sources. (Lesson pending; see Gaps in RESOURCES.md.)

Replication

src/mongo/db/repl/

Oplog local.oplog.rs (capped, idempotent entries). Secondaries pull from a sync source. PV1 elections are built on Raft. The majority commit point drives w:"majority" and readConcern:"majority".

Sharding

src/mongo/s/ (mongos), db/s/ (shard)

mongos routes by shard key. The balancer runs on the CSRS primary. Default range size is 128 MB, and a migration happens once shards differ by 3× that.

Phase 1 · The engine

Storage engine API

src/mongo/db/storage/

Collection → RecordStore. Index → SortedDataInterface. Snapshot and transaction → RecoveryUnit. Atomic group of writes → WriteUnitOfWork. Conflicts raise WriteConflictException and are retried with back-off.

WiredTiger

arch guide

B-trees. MVCC snapshots (snapshot isolation by default). Cache with eviction: workers first, then application threads past the trigger. History store WiredTigerHS.wt. Journal (WAL) synced every 100 ms. Checkpoints every 60 s.

Disk

dbPath

collection-<id>.wt and index-<id>.wt (one table per ident). journal/WiredTigerLog.NNNNNNNNNN (~100 MB each, snappy-compressed).
